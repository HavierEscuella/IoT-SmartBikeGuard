# 🚴 IoT Smart Bike/Scooter Guard — Архітектура та План Лабораторних Робіт

Цей документ описує концептуальну архітектуру, структуру коду та покроковий план реалізації вашого проекту **"Розумна вело-сигналізація" (IoT Smart Bike/Scooter Guard)** відповідно до вимог університетського курсу.

---

## 🎨 Дизайн-концепт та Колірна Гама (Premium Dark Tech)
Для IoT-додатків безпеки найкраще підходить сучасний **темний технологічний інтерфейс (Dark Glassmorphism)** з акцентними кольорами:
*   **Background (основа):** Глибокий темно-вугільний (`#121318`)
*   **Card / Sheet (картки):** Напівпрозорий сірий з розмиттям (`#1E202B` з opacity)
*   **Accent (безпека / активний):** Яскраво-бірюзовий або неоновий зелений (`#00E676` або `#00F2FE`)
*   **Warning (тривога):** Неоновий червоний/імпульсивний рожевий (`#FF1744` або `#FF5252`)
*   **Typography:** Сучасний шрифт `Outfit` або `Inter`

Для того щоб код був чистим та легко розширюваним від Лабораторної №1 до Лабораторної №5, найкраще структурувати проект за **фічами (features)**:

```text
│   │   ├── local_storage.dart   # Збереження стану (Lab 4)
│   │   └── api_client.dart      # Імітація/запити до IoT API (Lab 3)
│   └── utils/                   # Хелпери (форматування дат, GPS розрахунки)
│
├── features/                    # Функціональні модулі додатку
│   ├── alarm_keychain/          # Головний екран-брелок (Lab 1 & Lab 5)
│   │   ├── presentation/
│   │   │   ├── screens/dashboard_screen.dart
│   │   │   └── widgets/siren_button.dart
│   │   └── state/alarm_provider.dart
│   │
│   ├── auth/                    # Авторизація та реєстрація байка (Lab 2)
│   │   ├── presentation/
│   │   │   ├── screens/login_screen.dart
│   │   │   └── screens/register_bike_screen.dart
│   │   └── models/user_model.dart
│   │
│   ├── tracking/                # GPS моніторинг та маршрути (Lab 3)
│   │   ├── presentation/screens/map_screen.dart
│   │   └── models/bike_location_model.dart
│   │
│   └── settings/                # Налаштування чутливості та профілю (Lab 2 & Lab 4)
│       └── presentation/screens/settings_screen.dart
│
└── main.dart                    # Точка входу додатку
```

## 📅 Покроковий План виконання Лабораторних Робіт

### 🧪 Лабораторна робота №1: Базовий інтерфейс та Стан (StatefulWidget)
*   **Завдання в універі:** Створити додаток, додати текстове поле введення, яке впливає на інтерфейс, налаштувати лінтер та GitHub CI пайплайн.
*   **Як це адаптувати під вашу тему:**
    1.  **Створюємо екран "Брелока" (Dashboard):** У центрі велика кругла неонова кнопка стану сигналізації (Armed / Disarmed).
    2.  **Поле введення (Секретний PIN-код):** Користувач може ввести PIN-код або секретну фразу в поле:
        *   Введення **`1234`** або **`ARM`** — активує режим охорони (кнопка світиться зеленим, спрацьовує вібровідгук).
        *   Введення **`DISARM`** — знімає охорону.
        *   Введення **`SOS`** або **`Avada Kedavra`** — скидає стан до нуля, імітує екстрене вимкнення звуку або викликає миттєвий екран тривоги (червоне блимання).
    3.  **Додатково:** Додаємо лінтер `analysis_options.yaml` та GitHub CI `validation.yaml` з вашого репозиторію.

### 🧪 Лабораторна робота №2: Логін, Реєстрація та Профіль
*   **Завдання в універі:** Створити логін, реєстрацію та можливість редагування профілю.
*   **Як це адаптувати під вашу тему:**
    1.  **Login Screen:** Гарна форма входу власника.
    2.  **Bike Register Screen:** Форма реєстрації транспортного засобу (назва, тип: Велосипед/Самокат, серійний номер рами, фото байка, чутливість акселерометра).
    3.  **Edit Profile:** Редагування імені власника та контактного телефону для екстрених SMS.

### 🧪 Лабораторна робота №3: Інтеграція з IoT API (Завантаження даних)
*   **Завдання в універі:** Завантаження даних з API.
*   **Як це адаптувати під вашу тему:**
    1.  Створюємо **імітацію IoT API клієнта** (наприклад, через безкоштовні JSON mock-сервіси або локальний таймер, який імітує потік MQTT/HTTP повідомлень від датчиків байка).
    2.  **Дані, які завантажуємо:**
        *   Заряд батареї IoT-трекера (в %).
        *   Стан акселерометра (активний рух, спокій, кут нахилу).
        *   Координати GPS (для відображення на карті).
    3.  Відображаємо ці дані на Dashboard у реальному часі.

### 🧪 Лабораторна робота №4: Локальне збереження даних
*   **Завдання в універі:** Локальне збереження інформації.
*   **Як це адаптувати під вашу тему:**
    1.  Використовуємо `shared_preferences` або `hive` для збереження локальних даних.
    2.  **Що зберігаємо:**
        *   Токен авторизації та налаштування профілю користувача.
        *   Стан сигналізації (Armed/Disarmed), щоб при перезапуску додатку він зберігався.
        *   **Журнал тривог (Alarm Log):** історія подій (наприклад: *"Спрацював датчик руху о 14:23"*, *"Сирена активована віддалено о 18:01"*).

### 🧪 Лабораторна робота №5: Сповіщення та Алерти (Система тривоги)
*   **Завдання в універі:** Нотифікації користувача (алерти, попередження, діалогові вікна).
*   **Як це адаптувати під вашу тему:**
    1.  Реалізуємо **Екран Тривоги (Panic Screen)**: якщо байк рухається в режимі охорони, додаток переходить у режим червоного миготливого екрана з гучною сиреною (програвання звуку через телефон).
    2.  **Повідомлення:**
        *   Діалогове вікно з пропозицією швидкого виклику поліції чи перегляду карти.
        *   Локальні Push-сповіщення: *"Увага! Зафіксовано підозрілу активність!"*.

## 🛠️ Перший крок: Створення файлів для Лабораторної №1

Для того щоб здати першу лабу з вашим креативним підходом, ми можемо створити:
1.  `.github/workflows/validation.yaml` — автоматична перевірка коду (вже є у вашому шаблоні).
2.  `analysis_options.yaml` — правила лінтера.
3.  Оновлений `lib/main.dart` — з преміальним темним інтерфейсом брелока сигналізації, великою круглою кнопкою та інтерактивним полем введення PIN-коду.
